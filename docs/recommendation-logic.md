# 추천 로직 설계

계획서에 적은 목표는 "생활 패턴을 분석해 **최적화된** 구독 서비스를 추천"하는 것이었다.
그런데 처음 만든 로직은 그 목표에 못 미쳐서 3차 작업 때 전부 다시 설계했다.

---

## 1. 처음 로직이 왜 부족했나

| 항목 | 처음 | 문제 |
| --- | --- | --- |
| 판단 기준 | 1회당 비용 하나 | 많이 쓸수록 무조건 좋은 게 되어, "자주 쓰니 더 좋은 걸로 올리세요"라는 말이 나올 자리가 없다 |
| 결과 | 해지 후보다 / 아니다 | 요금제를 낮추라는 중간 선택지가 없다 |
| 데이터 | 서비스당 요금 하나 | 낮출 요금제가 데이터에 아예 없었다 |
| 대체 추천 | 무조건 더 싼 서비스 | 방향이 한쪽뿐이라 업그레이드를 못 한다 |
| 범위 | 구독 하나씩 따로 | 쿠팡 와우를 쓰면서 쿠팡플레이를 또 결제하는 중복을 못 잡는다 |

한마디로 **"구독을 줄이는 앱"이지 "최적화하는 앱"이 아니었다.**

---

## 2. 바꾼 것 ① — 요금제를 데이터로

서비스가 요금 하나를 갖는 대신 **요금제 목록**을 갖게 했다.
요금제마다 **광고 유무 · 화질 · 동시접속 · 오프라인 저장**을 같이 저장한다.

> 스펙까지 저장하는 이유: "낮추세요"라고만 하면 사용자가 **뭘 잃는지** 알 수 없다.
> 포기해야 하는 것을 같이 보여 주려면 가격만으로는 부족하다.

이걸 조사하다가 **가격만 보고 추천하면 사고가 나는 경우 두 개**를 찾았다.

1. **웨이브 베이직(7,900)은 광고형(5,500)보다 비싼데 화질이 720p로 낮고 동시접속도 1대다.**
   → 그래서 코드는 "다음으로 싼 요금제"가 아니라 **가장 싼 요금제**와
   **광고 없는 것 중 가장 싼 요금제**를 각각 고른다.
2. **티빙·왓챠 베이직은 동시접속 1대다.** 가족과 나눠 쓰면 낮추면 안 된다.
   → 동시접속이 줄어드는 변화는 반드시 문구로 알려 준다.

---

## 3. 바꾼 것 ② — '이용 강도'로 판정

이용 횟수를 **카테고리별 기준**과 비교해 네 단계로 나눈다.
같은 26회라도 음악은 평범하고 영상은 헤비 유저라서 하나의 기준으로 재면 안 된다.

| 카테고리 | 거의 안 씀 | 적당히 | 자주 | 기준을 그렇게 정한 이유 |
| --- | ---: | ---: | ---: | --- |
| 영상 스트리밍 | 1~2회 | 3~7회 | 8회~ | 주 2회(월 8회) 이상이면 자주 보는 편 |
| 음악 | 1~5회 | 6~15회 | 16회~ | 음악은 매일 듣는 사람이 많아 기준이 높다 |
| 쇼핑·배달 | 1회 | 2~4회 | 5회~ | 무료배송 한 번에 3천원쯤 아끼니 월 2~3회면 회비는 뽑는다 |
| AI·생산성 | 1~3회 | 4~10회 | 11회~ | 주 1회 이하면 굳이 유료로 둘 이유가 적다 |

**1회당 비용은 판정 기준에서 뺐다.** 참고 지표로만 보여 준다.
많이 쓸수록 무조건 좋다고 하면 "올리세요"라는 추천이 나올 수 없기 때문이다.

---

## 4. 바꾼 것 ③ — 추천을 다섯 가지로

| 강도 | 추천 | 실제로 나오는 예 |
| --- | --- | --- |
| 한 번도 안 씀 | **해지** | 티빙 0회 → 해지, 13,500원 절약 |
| 거의 안 씀 | **해지** 또는 가장 싼 요금제로 | |
| 적당히 씀 | **요금제 낮추기** | 넷플릭스 프리미엄 17,000원을 월 4회 → **광고형 7,000원으로**, 10,000원 절약 |
| 보통 | **유지** | |
| 자주 씀 | **요금제 올리기** 또는 **더 폭넓게 쓰이는 서비스로** | 쿠팡플레이 월 20회 → 넷플릭스로 갈아타기 |

이용 시간(분)을 적어 두면 판단이 더 정확해진다.
한 번에 평균 30분도 안 보는 사람에게는 "화질과 동시접속을 다 쓰고 있지도 않다"는
근거를 추천 문구에 덧붙인다.

---

## 5. 바꾼 것 ④ — 구독 하나가 아니라 전체를 보기

구독을 따로따로만 보면 절대 못 찾는 낭비가 세 종류 있다.

| 종류 | 무엇을 찾나 | 예 |
| --- | --- | --- |
| **중복 결제** | 이미 다른 멤버십에 들어 있는 걸 따로 결제 | 쿠팡 와우를 쓰면서 쿠팡플레이를 또 결제 → 7,890원 |
| **묶음 상품** | 묶음으로 사면 더 싼 경우 | 넷플릭스를 따로 내는 사람에게 네이버플러스(4,900원) 제안 → 2,100원 |
| **너무 많음** | 같은 카테고리를 3개 이상 들고 있는데 다 합쳐도 잘 안 씀 | OTT 3개인데 총 5회 → 하나만 남기기 |

> **여기서 로직 충돌을 하나 발견해서 고쳤다.**
> 쿠팡플레이는 와우에 포함돼 사실상 공짜인데, 자주 본다는 이유로
> "넷플릭스로 갈아타세요(+5,610원)"를 추천하고 있었다.
> 공짜로 쓰는 것에 돈을 더 쓰라는 말이 되어 버린다.
> → 이미 묶음에 포함된 서비스는 **다른 추천을 전부 막고** "따로 내는 결제만 멈추기"만 보여 준다.

---

## 6. 습관 유형

위에서부터 차례로 확인해서 처음 걸리는 유형으로 정한다.

| 유형 | 기준 | 한 줄 |
| --- | --- | --- |
| 방치형 | 한 번도 안 쓴 구독이 1개 이상 | 결제는 하지만 손은 잘 안 가요 |
| 과금형 | 손볼 구독이 전체의 절반 이상 | 쓰긴 쓰는데, 지금 요금이 이용량에 비해 큽니다 |
| 몰입형 | 자주 쓰는 구독이 전체의 절반 이상 | 본전은 확실히 뽑고 계세요 |
| 알뜰형 | 손볼 구독이 하나도 없음 | 낸 돈만큼 알차게 쓰고 있어요 |
| 무난형 | 나머지 | 크게 손해 보고 있진 않아요 |

'한 번도 안 쓴 구독'이 다른 어떤 신호보다 강한 낭비 신호라고 보아 맨 위에 두었다.

---

## 7. 내가 정한 기준값들 (정답이 없는 판단)

계획서 6번에 "정답이 없는 판단은 근거를 적어 두겠다"고 썼는데, 실제로 이만큼 나왔다.

| 정한 것 | 값 | 근거 | 어디를 고치면 되나 |
| --- | --- | --- | --- |
| 카테고리별 이용 강도 경계 | 위 표 | 카테고리마다 '보통'이 다르다 | `INTENSITY_LIMITS` |
| 콘텐츠 규모 점수 | MAU 기반 1~5 | 작품 수가 공개돼 있지 않아 실측치인 이용자 수를 대신 씀 | `Service.reach` |
| 이용 0회 처리 | 나눗셈 대신 '계산 불가' | 억지 숫자보다 가장 강한 해지 신호로 따로 다룸 | `costPerUse` |
| 달력 기록 vs 몰아 입력 | 몰아 입력 우선 | 더 나중에, 더 정확하게 알려 준 값. 단 화면에 표시함 | `countUsage` |
| 요금제 낮추기 후보 | 가장 싼 것 + 광고 없는 것 중 가장 싼 것 | 웨이브 베이직 같은 함정을 피하려고 | `downgradeTargets` |
| 절약 예상액 | 아끼는 추천만 합산 | 올리기는 돈을 더 쓰는 것이라 제외 | `maxSaving` |

---

## 8. 아직 못 하는 것

- **동시 시청 기기 수를 모른다** → "4인 요금제인데 혼자 쓰니 낮추세요"는 근거 없이 말할 수 없다.
  구독 등록할 때 "몇 명이 같이 쓰나요?"를 받으면 가능해진다.
- **어떤 콘텐츠를 봤는지 모른다** → "해외 드라마만 보니 넷플릭스가 맞다" 같은 추천은 불가능하다.
  계획서 Input에 있던 '콘텐츠 카테고리'가 아직 빠져 있다.
- **MAU는 인기이지 콘텐츠 양이 아니다** → 왓챠처럼 독립·예술영화가 강한 서비스는
  "콘텐츠가 적다"가 아니라 "취향이 다르다"가 맞다. 그래서 화면 문구도
  '콘텐츠가 많은'이 아니라 '**더 폭넓게 쓰이는**'으로 썼다.
- **쇼핑·AI 카테고리는 갈아타기 추천이 안 나온다** — 이용자 수 자료를 못 찾아
  `reach`를 비워 뒀기 때문이다. 없는 근거로 추천하느니 안 하는 쪽을 골랐다.
